# Результат на конкурсном наборе

Файлы этой папки — то, что раздел 7.2 ТЗ требует приложить к сдаче: выгрузка результата
на конкурсном наборе `data/samples/dataset_lct2026.geojson` (скорректированный датасет
от 18.09).

Они не собираются руками и не правятся: каждый получен из работающего сервиса одним
запросом.

| Файл | Что это | Как получен |
|---|---|---|
| `result_lct2026.geojson` | обычный расчёт: три варианта, четыре типа объектов раздела 7.1 ТП | `GET /api/v1/jobs/{id}/result.geojson` |
| `result_lct2026_depth.geojson` | дополнительный режим с учётом глубины: отдельное ранжирование, глубины концов участков | тот же запрос по расчёту с `withDepth: true` |
| `statement_lct2026_best.csv` | ведомость объёмов работ по лучшему варианту — таблица для Excel | `GET /api/v1/jobs/{id}/statement.csv` |
| `presentation/index.html` | презентация к защите | открыть в браузере; `Ctrl+P` → «Сохранить как PDF», альбомная, поля «нет», фоновая графика включена |

## Что в результате

Обычный расчёт, все три варианта подключают все семнадцать точек.

| Показатель | Лучший вариант (v1) |
|---|---|
| Точек подключения | 17, подключены все |
| Решение | одна сеть, присоединение в участок 126 новой камерой |
| Новая сеть | 1 728,4 м, 29 участков, 13 камер |
| Врезок в существующие камеры | нет: присоединение выполнено новой камерой, её стоимость включает присоединение |
| Стоимость | участки 197 579 372 ₽ + камеры 51 000 000 ₽ = **248 579 372 ₽** |
| Штраф | 0 |
| Показатель ранжирования S | **12,145** |
| Время расчёта | около 23 с; первый расчёт после запуска до 35 с, пока прогревается JVM |

Второй и третий варианты отличаются не смещением трассы, а стратегией: разделение сети
на две части даёт S = 12,244, на три — S = 12,491. Разбор стоимости и формула `S`
построчно — в панели вариантов интерфейса.

Режим с учётом глубины ранжируется отдельно, как требует раздел 5 приложения. Там
лучшим оказывается вариант из двух независимых частей: S = 12,244, сеть 1 710,2 м,
стоимость 254 064 260 ₽, расчёт около 22 с. Его трасса идёт на обычной глубине 3,0 м
целиком — вертикальный манёвр ей не понадобился. Отклонение до 2,04 м есть у варианта,
занявшего в этом режиме второе место: там один подъём поверх существующей сети
на участке `new_v1_4`, с просветом 0,51 м при норме 0,50 м.

## Проверка выгрузки

Выгрузка проверяется независимой реализацией правил приложения — правила в ней записаны
заново по тексту, а не взяты из кода сервиса:

```bash
python tools/validate_result.py deliverable/result_lct2026.geojson \
    --dataset data/samples/dataset_lct2026.geojson
```

На обычной выгрузке это 1 916 проверок, на выгрузке с глубиной 2 071, нарушений нет
ни в одной. Проверяются состав типов и атрибутов, отсутствие Z-координат, совпадение
длины с геометрией, предел угла поворота, пропускная способность выбранного ДУ,
стоимость каждого участка по цене метра, диаметр и стоимость каждой камеры по шкале,
правило четырёх примыканий с учётом транзитной существующей линии, монотонность ДУ
и предельная длина по каждому пути от места присоединения, сходимость всех сумм сводки
и формула показателя.

## Как воспроизвести

```bash
cp .env.example .env
docker compose up -d --build
```

Дальше — интерфейс на http://localhost:3000: загрузить набор, нажать «Запустить
расчёт», выгрузить результат. То же через API описано в Swagger на
http://localhost:8080/swagger-ui.html.

Проверка того, что всё это собирается и работает на чужой машине с нуля:

```bash
bash ops/clean_room_check.sh
```
