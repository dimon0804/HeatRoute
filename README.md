# HeatRoute

Сервис автоматического построения вариантов подключения перспективных ОКС
к существующей тепловой сети.

Конкурсный кейс «Сервис моделирования трасс подключения к тепловым сетям»,
«Лидеры цифровой трансформации» 2026.

На вход — один GeoJSON с существующей сетью, камерами, перспективными ОКС, точками
подключения и пространственными ограничениями. На выходе — до трёх ранжированных
вариантов новой сети с маршрутами, точками врезки, камерами, расходами, условными
диаметрами, участками реконструкции существующей сети и полной стоимостью.

---

## Быстрый старт

```bash
cp .env.example .env
docker-compose up -d --build
```

| Что | Адрес |
|---|---|
| Интерфейс с картой | http://localhost:3000 |
| Swagger UI | http://localhost:8080/swagger-ui.html |
| Состояние сервиса | http://localhost:8080/actuator/health |

Конкурсный набор для проверки лежит в `data/samples/dataset_lct2026.geojson`.

### Разработка бэкенда без Docker

```bash
cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=nodb   # без базы данных
mvn test                                              # тесты
```

## Структура репозитория

```
backend/     Java 11 + Spring Boot 2.6.3 — разбор, расчёт, API, выгрузка
frontend/    React + TypeScript + Vite + MapLibre — карта, варианты, диагностика
ops/         Dockerfile бэкенда и фронтенда
docs/        документация решения; docs/research — исходные материалы кейса
data/        конкурсный набор и примеры выгрузок
tools/       служебные скрипты разведки и проверки данных
```

Читать в таком порядке:

1. [`docs/00_CASE_BRIEF.md`](docs/00_CASE_BRIEF.md) — кейс, правила, справочные числа, чек-лист сдачи
2. [`docs/01_ARCHITECTURE.md`](docs/01_ARCHITECTURE.md) — слои, ключевые решения, тесты
3. [`docs/02_ALGORITHM.md`](docs/02_ALGORITHM.md) — расчётное ядро от свободного пространства до ранжирования
4. [`docs/03_ROADMAP.md`](docs/03_ROADMAP.md) — что сделано и что дальше
5. [`docs/research/dataset_report.md`](docs/research/dataset_report.md) — разбор конкурсного набора

## Соответствие требованиям ТЗ

Стек задан разделом 3.2 ТЗ и выдержан без отклонений: Java 11, Spring Boot 2.6.3,
PostgreSQL, springdoc-openapi-ui 1.7.0, docker-compose, Ubuntu Server 22.
Входной файл до 3 ГБ обрабатывается потоково, через временное дисковое хранилище;
выгрузка до 500 МБ пишется в поток ответа.

Координаты, идентификаторы и конфигурация конкурсного набора нигде не зафиксированы
в коде (требование раздела 2.14). Справочник технического приложения вынесен
в `backend/src/main/resources/reference/heatroute-reference.yml` и подменяется снаружи.
